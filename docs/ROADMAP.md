# Roadmap

路线按“每一步都有可展示结果”安排，而不是一次性堆满技术名词。

## 第 1 周：工具操作基线

- 固定随机种子，完成工具拾放任务和脚本专家
- 统一成功判据、步数、终点误差和安全干预指标
- 保存可复现实验命令与一段演示视频

交付证据：代码、自动化测试、20 个 episode 的基线结果。

## 第 2 周：数据闭环

- [x] 采集训练、验证、测试 episode，禁止按相邻帧随机切分
- [x] 失败样本分类写入评测输出
- [x] 数据集记录环境版本、随机种子和任务参数
- [ ] 轨迹 JSON 回放与失败案例可视化

交付证据：`collect` 产生的 `*.json` 元数据，以及 E001 的失败分类。

## 第 3 周：表面清洁基线

- [x] 建立参数化平面擦拭任务和名义轨迹
- [x] 随机化目标位姿、表面尺寸、摩擦与控制延迟
- [x] 统计覆盖率、接触丢失、过力次数和轨迹平滑性

交付证据：E001，oracle 与 4 cm 噪声名义轨迹的对照。

## 第 4 周：行为克隆与残差策略

- [x] 名义轨迹 + 有界残差接口
- [x] CPU 上的 NumPy MLP 训练闭环
- [ ] 残差策略在固定测试集上超过名义轨迹
- [ ] 定义 ROS2/真机适配器接口，但不伪造硬件验证

交付证据：E002/E003。当前结论是流水线可运行，性能尚未超过名义轨迹。

## 后续

- 在可用的 Linux/GPU 环境中评估 ACT 或 Diffusion Policy。
- 接入原项目的数据字段与 ROS bag 回放。
- 获得 xArm 硬件后验证策略权限、安全边界和迁移误差。

## 暂不做

- 双臂协同：会同时放大动作空间、数据量和调试成本。
- Isaac Sim：当前 macOS 硬件不适用。
- 从零训练 VLA：与现有算力和项目证明目标不匹配。
- 宣称 Sim-to-Real：必须在真实硬件上完成验证后才能使用该表述。
