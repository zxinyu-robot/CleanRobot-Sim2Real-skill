# 从 clean-robot 到学习增强操作

新仓库不是替代既有工程，也不直接复制其 ROS1 脚本；它负责补上机器人学习与实验评测这一层。

## 已有工程基础

`clean-robot` 原型已经覆盖真实复合机器人任务中的多项能力：

- xArm 关节与笛卡尔轨迹执行、工具取放
- RealSense 深度图、相机内参与像素反投影
- TF 坐标变换和目标在机械臂基座坐标系下的定位
- YOLO 检测结果接入
- 移动底盘导航、里程计移动和墙面对齐
- 清洁执行器服务调用
- 洗手盆、小便池等多阶段任务流程

它证明的是机器人感知、导航、机械臂和末端设备的系统集成经验。

## 需要补足的问题

原型主要采用硬编码点位、阈值和顺序脚本。面对目标定位误差、接触变化或新清洁对象时，需要人工重新调参，且缺少统一数据记录和量化评测。

新仓库聚焦三个增量：

1. **数据闭环**：统一记录观测、动作、任务阶段、失败原因和随机种子。
2. **学习增强**：保留可解释的名义轨迹，让策略只预测受约束的残差修正。
3. **统一评测**：比较固定轨迹、行为克隆和残差策略在扰动下的成功率与安全性。

## 技术路线

### M0：工具拾放

当前 MuJoCo 任务对应原工程的取工具和还工具阶段，用最小环境验证策略接口、安全层、示范采集和评测链路。

### M1：表面清洁

已完成平面擦拭任务和参数化名义轨迹。E001 显示：真值位姿下覆盖率约 0.92、成功率 100%；4 cm 检测噪声下名义轨迹成功率 0%、覆盖率约 0.62。

核心指标：

- 表面覆盖率
- 接触丢失率
- 过大接触力次数
- 轨迹平滑性
- 任务完成时间

### M2：残差策略

策略不直接生成完整轨迹，而是输出：

```text
安全动作 = 名义轨迹动作 + 有界残差修正
```

这能利用已有工程中的规则轨迹，并限制学习策略的权限，适合从仿真向真实系统渐进迁移。

### M3：系统适配

在 Ubuntu/ROS2 环境中，将策略封装为独立节点：

```text
感知快照 -> 任务编排 -> 名义轨迹/策略 -> Action Shield -> xArm 控制器
```

当前无硬件时只定义接口和回放测试。只有重新接入真实 xArm 并完成实验后，才将项目描述为 Sim-to-Real。

## 面试价值

这条主线同时展示两类能力：

- 已有：真实机器人系统集成、感知坐标链路、任务流程和执行器控制。
- 新增：仿真建模、示范数据、模仿学习、残差策略、安全约束和实验方法。

相比单独做一个通用抓取 Demo，它能解释为什么选择该任务、旧系统的瓶颈是什么，以及学习方法实际解决了什么问题。
