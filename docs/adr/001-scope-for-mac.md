# ADR-001：先做原生 MuJoCo 单臂闭环

- 状态：已接受
- 日期：2026-10-14

## 背景

已有复合清洁机器人原型涉及 xArm、RealSense、移动底盘、ROS1 感知与执行链路，但当前只有一台 4 核 Intel i5、8GB 内存的 macOS 电脑，无法使用原有机械臂、RGB-D 相机或 Linux/CUDA 工作站。

项目的近期目标是基于既有系统工程经验，为具身操作岗位提供可信的机器人学习在做证明，而不是追求论文级结果。

## 决策

第一阶段采用原生 MuJoCo、NumPy 和简化笛卡尔吸盘机构，实现与原工程取放工具阶段对应的单臂拾放任务。系统保留环境、策略、安全层和评测层之间的明确接口；随后扩展到学习增强的表面清洁轨迹。

## 原因

- MuJoCo 官方提供 macOS x86_64 预编译包，可在当前机器直接运行。
- 原生接口依赖少，便于理解动力学、控制周期和接触问题。
- 单臂任务足以验证数据采集、策略执行、安全约束和实验评测。
- 简化机构让 CI 和旧电脑都能快速运行，适合持续提交。

## 未选择的方案

依据 2026-10 的平台核对（Intel Mac、macOS 14、无 CUDA、无真机）：

### 双臂 ACT

没有硬件和 GPU 时，数据真实性与训练成本都无法支撑。原始 ACT/ALOHA 依赖双臂遥操作和闭环视觉；本机再复现一份双臂仿真，证明不了真实双臂能力。

### robosuite

官方支持 macOS 和无 GPU，任务与示范工具更现成，也是合理备选。本仓库要复现 clean-robot 的「检测点 + 固定清洁轨迹」，需要自己的污渍网格、接触指标和残差接口；再引入 robosuite 1.5 的 `mujoco>=3.3,<3.10` 约束，收益不足以覆盖定制成本。后续若做标准抓取对照，可以再加一层包装，而不是替换现有任务。

### ROS2 + MoveIt2

对机器人系统岗位有价值，但 macOS 不是主要部署环境。本阶段先定义清晰接口，后续在 Ubuntu 环境增加适配器。

### Isaac Sim

主机不支持 macOS；最低配置也远超当前 8GB Intel 机器。排除。

### ManiSkill

macOS 支持仍偏实验性，弱核显上的 Vulkan/MoltenVK 不稳定，且现代 PyTorch 依赖与 Intel Mac 冲突。不作为主栈。

### 最新 LeRobot / 新版 PyTorch

LeRobot 0.5.x 要求较新的 PyTorch（文档侧已到 2.7–2.10）。PyTorch 从 2.3 起不再发布 macOS x86_64 官方包，Intel Mac 最后一个官方版本是 2.2.2。因此最新 LeRobot 不能作为本机主路径。本仓库用 NumPy MLP 跑通残差训练闭环；数据格式保持可迁移，完整模仿学习放到 Linux/GPU 再做。

实测补充：MuJoCo 3.15 在这台机器上没有可用 Intel wheel，当前锁定 `mujoco>=3.3,<3.4`（已验证 3.3.7）。

## 后果

优点是可以快速形成端到端证据和稳定迭代；代价是简化机构不能代表真实机械臂动力学，也不能据此声称完成 Sim-to-Real。README 和面试表述必须明确这一边界。
